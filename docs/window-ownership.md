# Qualified window ownership

T20 implements one active supervision window per physical local checkout. A second window reports **Collection passive · another window owns this checkout**, with a Source Health explanation. It neither installs another producer nor consumes the inbox; disabling/closing it cannot stop the owner. Independent editor profiles retain the root's established collector identity rather than conflicting with its journal.

Explicit Enable is remembered in editor workspace state. Normal host shutdown removes the owned hooks and disables publication while preserving that choice; reload resumes only in the same eligible trusted, single-folder fixture. Explicit Disable clears the choice. Native delivery still starts at **awaiting first native event** after replay/resume.

Exclusive leases record a process ID and random token in private storage. Recovery requires a strictly valid lease and an operating-system **ESRCH** result for that exact process ID, followed by existing token/inode checks during acquisition. Active processes, reused live PIDs, permission-denied inspection, malformed/public/symlink leases and competing replacement remain unstealable. PID absence is conservative, not a distributed lease protocol; remote/network storage remains unsupported.

A private ownership record binds generated hook bytes to the physical root and storage directory. Interrupted upgrades preserve at most the old and replacement generated configurations until the new installation commits. Previous executable paths are compared as data; replacement always uses the current extension-owned helper. Without structural proof, existing/modified hooks are preserved and enable refuses. The original absence is recorded explicitly; the next configuration task extends reviewed existing-config handling.

The helper and collector now accept exactly one matching enabled root. Unrelated, nested-only and mixed multi-root contexts do not persist source metadata just because a hook was invoked. File hints still require the compiled fixture privacy policy; physical worktrees remain distinct. Broad plugin registration is not used in the selected explicit project-hook integration.

Verification: 143 unit tests, 19 process tests and Go tests passed. A real process SIGKILL/upgrade test verifies dead-lease recovery across collector profiles. [Two installed Cursor windows](t20-window-verification.json) prove passive ownership and preservation of the owner's config; their restart check uses explicit reenable because extension-test mode resets mementos. A separate [normal development-window UI check](t20-normal-window-reload.json) proves automatic resume across Developer Reload Window without re-enabling. All named test collectors were disabled and owned hooks/leases removed. Historical T03 supplies native Agent two-window delivery evidence; T20 makes no additional ordinary Agent/model call claim.
