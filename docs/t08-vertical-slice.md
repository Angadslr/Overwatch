# T08 native file-supervision slice

Implemented and verified for Angad on 22 October 2026. T08 and G1 are complete in development mode on Cursor 3.26.16, editor API 1.128.0, extension-host Node 24.19.0, macOS 26.5.2 arm64. This is the historical T08 verification record; T09/T10 were subsequently completed on 23 October. See [identity/path implementation](identity-and-paths.md) for the current scope.

## Run and boundaries

Run `npm run supervision:launch`, trust the named invented fixture, then use **Agent Supervision: Enable in Fixture Workspace**. Ordinary native Agent Chat can read `read.txt` and edit `edit.txt`; the native Activity Bar tree shows source-session identity, relative path, evidence and age. Clicking a known fixture row opens its current file. **Agent Supervision: Save Collection Report** saves bounded metadata and render-request samples in private fixture storage. Resolve pending invented edit reviews, then use **Agent Supervision: Disable and Reload Fixture Window** to finish.

The implementation uses the qualified explicit project-hook fallback because the plugin registration API is unavailable. No CLI agent substitutes for native delivery. Collection requires a trusted local single-root invented fixture and an executable helper. Existing hooks and competing live collector ownership are never replaced. Disable first turns off the private publisher configuration, then removes only the unchanged owned hook inode/bytes and closes the lease. Modified hook files are preserved. Cached helper invocations cannot publish after disable; reload clears the cached commands.

The six allowed names are `read.txt`, `edit.txt`, `shared.txt`, `missing.txt`, `created.txt` and `renamed.txt`. Their known absolute/relative hashes map locally to those invented names. Opening rechecks trust, workspace, marker, root and target; missing files are reported without creating them, and symlinks are refused. General path containment, canonical identity, exclusions and worktree policy remain T10. Stable aliases/child lifecycle relationships remain T09. The full product layout remains T13; ownership recovery remains T20/T21 and alpha packaging remains T24. The discovery VSIX excludes the Go helper and is not the T08 installation route.

## Actual verification

- Strict generated contracts/types and build passed; 48 unit tests and 10 real-process integration tests passed. New cases cover owned cleanup, competing collectors, existing/modified hooks, lost eligibility, unsafe fixture paths, native metadata replay and the manifest container identifier.
- `npm run test:extension` passed seven checks in the actual installed Cursor extension host. It verifies owned enable, real TreeItems, correct editor opening, accurate missing results, no content-marker leakage, disable and cached-command behavior. These tests inject synthetic hook input and explicitly record `nativeDelivery: false`. The trusted host was exercised; untrusted eligibility is covered by unit tests, not claimed as a live untrusted-host run. See [host result](t08-extension-host-verification.json).
- The named **T08 native vertical-slice smoke test** ran through ordinary native Agent Chat on 22 October at approximately 13:40–13:42 PDT. A native read/edit pair completed in about five seconds. Thirteen journal records projected into five operations across two files: three source-completed reads, one completed edit tool and one independent edit report. The extra reads came from the native edit workflow. These counts preserve separate evidence rather than treating an edit report as saved or accepted.
- Source-session identity, relative paths, evidence and age were observed in the same window. Selecting the read row opened the intended current `read.txt`. The invented edit was kept before reload; this manual review action does not establish an acceptance signal in telemetry.
- Disable/reload left publisher configuration disabled, owned hooks and collector lease absent, and zero ready files. A subsequent ordinary native read completed in about two seconds, with the journal unchanged at 13 records. The fixture window remains available for inspection, with collection off. No real-project or global hook configuration was changed.

The sanitized [native evidence fixture](../tests/fixtures/cursor/t08-journey.json) contains validated projected source records, bounded view metadata, measured timings and cleanup results. It retains no prompts, file bytes, tool outputs or native response text. The authoritative telemetry is the source journal; the UI projection is replayable and deduplicated. Disk persistence, acceptance and child-to-file ownership remain unknown.

## Latency and G1 effort review

Six first `TreeDataProvider.getTreeItem` requests arrived 110–217 ms after hook receipt. This measures receipt to the editor requesting a TreeItem, not pixel paint. The first screen observation saw the read at age 16 seconds and the edit report at age 13 seconds, giving visibility upper bounds below 17 and 14 seconds respectively, including the automation observation delay. This small run establishes no p95, CPU/memory budget, comparative hook overhead or final performance target. The five-second native turn and two-second disabled read are observations, not a controlled overhead comparison.

The initial 3–5-file estimate was too small once integration ownership, trust/path checks and both host/native verification were included. Work was split into integration/UI and verification slices. Keep T09/T10 focused on identity/path policy, retain full layout work in T13 and measure sustained performance later. Do not generalize the fixed fixture mapping into production path identity.

Manual review and runtime verification corrected event forwarding, an invalid Activity Bar container identifier and test storage shared across isolated editor profiles. The manifest regression now has coverage. Each test profile owns a separate fixture/storage directory; each injected journey also has a fresh source identity, so a repeat run cannot pass against stale history. Collection is explicitly enabled and never starts automatically.
