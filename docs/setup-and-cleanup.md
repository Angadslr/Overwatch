# Setup and cleanup

T21 verified 25 October 2026. Supported collection still requires a trusted, local, single-folder, macOS arm64 invented fixture on the qualified Cursor build. No workspace-configured helper path is executed: setup uses the extension's compiled helper. Restricted, remote, virtual, symlinked and unsupported setups refuse collection. See [window ownership](window-ownership.md) for reload and competing-window behavior.

Run **Agent Supervision: Enable in Fixture Workspace**. Enable records the choice for normal host reload; **Disable** clears it. Privacy exclusion changes immediately restrict collection, clear frozen/open metadata, stop the producer and clear the recorded enable choice. Enable again explicitly after reviewing exclusions. Disabling stops cached commands through the publisher flag before restoring/removing hooks, quiesces ingestion, writes the bounded checkpoint and releases the lease.

Existing `.cursor/hooks.json` is preserved and refused by default. To opt in, review its contents and set `agentSupervision.allowExistingHooks` to `true` in the fixture's workspace settings. Only valid version-1 JSON with an object of hooks is eligible; duplicate keys, comments/trailing commas, malformed known hook arrays, unsafe files and ambiguous prior supervision commands refuse without changing the original. Unknown root/hook keys and existing permission command entries retain their values and order. Observation entries append to supported arrays; no foreign command is executed by setup or self-check. Cursor retains responsibility for running existing user hooks and their permission behavior.

Before replacement, a mode-0600 private `hook-ownership.json` records the exact original UTF-8 bytes (or explicit absence), root/storage bindings and recognized generated configurations. The backup may contain sensitive user hook configuration; it is deliberately excluded from collection reports and telemetry. Original input is bounded to 32 KiB; generated hook configuration to 64 KiB; the ownership record read to 256 KiB. The bundled parser uses its supplied module entry so deployment does not depend on Node resolving unbundled internal parser imports.

Installation writes and syncs a private staging file, then replaces only the compared configuration or links into an absent destination without replacement. A directory sync commits the new entry. Disable compares both current inode and exact installed bytes before restoring the original byte-for-byte, or removing an originally absent configuration. A later edit or replacement remains intact; collection is disabled and the original backup is preserved for review. Do not copy a stale backup over a changed file. Owned staging can be reclaimed only when its bytes match the durable original/generated proof; unknown staging is preserved and installation stops. Same-user malicious concurrent processes are not an isolation boundary.

Verification: 149 unit tests, 19 process tests and [35 installed Cursor checks](t21-extension-host-verification.json), plus the T20 normal-window reload proof. Cases include unknown hook keys, foreign permission entries, invalid/duplicate/versioned JSON, trust changes, symlink directories, post-install modifications, repeated setup, interrupted replacement/linking, helper upgrade and absence of invented backup secrets from default diagnostics. The named T21 test fixture was stopped with publisher disabled, hooks/lease absent and inbox empty. No ordinary Agent turn or new native coverage is claimed by this configuration suite.
