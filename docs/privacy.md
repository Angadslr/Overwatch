# Metadata-only privacy and reviewed local maintenance

Collection is explicit, local, trusted, and restricted to invented fixtures. Native path collection remains limited to the six previously qualified names; this task does not enable arbitrary native file discovery.

## Policy and persistence

`agentSupervision.pathExclusions` accepts at most 100 relative path globs, each at most 256 characters. Default exclusions cover integration directories, secret directories, environment files, private keys and credentials. Invalid settings refuse enable. A setting change synchronously restricts journal admission, clears affected file projections and local observations, then stops collection. Explicit enable compiles the new policy and resumes collection.

The extension compiles approved relative and absolute fixture spellings into a sorted allowlist of at most 12 SHA-256 hints. Private `publisher.json` contains `privacyVersion: 1`, a digest over the source root hash and allowlist, and no raw root, path, exclusion pattern or contents. Only the collector lease owner atomically upgrades an older publisher configuration. Older helper binaries reject the added configuration fields instead of collecting without the policy.

The Go helper answers the hook before doing telemetry work. Its bounded parser temporarily extracts allowlisted source fields; unknown keys, arbitrary exceptions, contents, prompts, commands, output, reasoning and email are dropped. Before producing a path hash, the helper checks policy membership, the declared root and the current file type. Symlinks and unresolved unsafe targets are refused; an approved missing leaf remains only a source hint. No contents are read. A mixed allowed/excluded input suppresses the whole path hint. Multiple distinct approved hints remain ambiguous.

Missing, invalid or stale policy removes the path hint and reports `policy-unavailable`. Excluded paths report `excluded-path`; unsafe resolution reports `path-unresolved`. These are fixed enums, never raw exceptions or locators. The publisher checks the policy again immediately before envelope construction. The ingester refuses path-bearing records with another policy digest or an unapproved hint before journal append. Disabling the publisher prevents cached commands from collecting; the old Node discovery entrypoint is response-only and the old content-derived editor timing recorder is no longer activated.

Reduced collection preserves bounded safe health metadata and opaque IDs. Privacy-blocked source records normalize to coarse self-check events, never file operations or inferred actor claims. Health reports counts of exclusions, policy gaps and unresolved targets. Native delivery and partial source coverage remain separate health dimensions.

## Replay and diagnostics

The immutable journal is not rewritten when settings change. Previously collected hashes may remain in historical storage; a newly restrictive policy prevents them from reappearing as file activity or decorations. An event admitted before a policy change is historical data, not retroactively erased. T19 supplies bounded retention; T23 supplies explicitly reviewed workspace history deletion below. Stronger same-user adversary isolation remains outside the qualified profile.

Local filesystem/editor observations use the same exclusion settings before queueing and after canonical resolution. They remain bounded host memory with unknown actor. Default collection reports omit **all** local relative paths and file keys, along with tree labels/descriptions that could contain them. Reports retain bounded event IDs, scope IDs, phases, metrics, evidence, lifecycle and health. Hashes are opaque locators, not anonymity guarantees or canonical file identity.

## Reviewed local export (T23)

Run **Agent Supervision: Preview Local Diagnostic Export**, choose **Redact paths** (the default) or explicitly include normalized relative paths, then inspect the read-only JSON preview. Its manifest lists the exact categories, omissions, limits and exclusion counts. **Agent Supervision: Save Reviewed Local Export** saves those exact bytes under this workspace's private `.local/supervision-storage/exports/` directory. No upload or network request occurs. **Agent Supervision: Cancel Diagnostic or History Review** invalidates the review without saving it.

The allowlisted projection contains a qualified editor API version, coarse health and readiness codes/counters, at most 2,000 normalized source events and 500 independent local observations. It preserves evidence, times, phases and unknown actors/outcomes. Identifiers are consistently pseudonymized by field category. This deterministic hashing is not an anonymity guarantee. Unknown source names, arbitrary fields and invalid events are not copied. Default exports omit all path locators, native path hashes and file keys. Optional relative paths come only from validated normalized targets and remain subject to current exclusions; native hashed hints are never expanded into paths.

Prompts, reasoning, file contents, tool input/output, transcripts, email, exception text, user-defined aliases, hook configurations, original-hook backups and native conversation storage are omitted. The export is a bounded JSON snapshot, not a journal archive. The preview is limited to 4 MiB; saved exports are limited to 20 files and 20 MiB total. Directories use mode 0700 and saved files 0600 on the qualified local platform. Unsafe/symlinked destinations refuse saving.

A review is single-use and expires after five minutes. Privacy changes, pruning, reset, cancellation or a changed storage generation invalidate it. New observations do not silently alter the reviewed bytes. Saving checks exclusive workspace ownership and the storage/privacy epoch again around atomic publication; stale staging is removed. A disabled window discards stale in-memory observations if another window has reset that checkout, including before its first export review.

## Reviewed workspace history deletion (T23)

Run **Agent Supervision: Preview Clear Owned History**, choose whether to keep saved exports (the default) or include them, then review the exact workspace, categories, artifact count/bytes and preserved unknown entries. Preparing the review disables collection and holds the workspace's exclusive lease for at most five minutes. **Agent Supervision: Clear Reviewed Owned History** requires a separate modal confirmation. Cancellation releases the lease and preserves history; collection remains off. Re-enable explicitly after a completed or cancelled review.

The selected scope includes recognized source journal segments and retention/dedup metadata, the projection checkpoint, diagnostic report, pending current-generation and legacy flat-inbox telemetry, producer-loss markers, and export staging. Saved generated exports in this workspace's private export directory are removed only when selected. Completion also clears this window's source/local projections, aliases, attention history/preferences, filters, frozen view and details. Counts describe the preview; later artifacts within the same selected categories are included at commit, as disclosed in the review.

User files, foreign hooks, exact original-hook backups and native conversations are outside the deletion scope. Publisher routing/privacy configuration and package binaries remain so collection can be explicitly enabled again. Unknown files are preserved. Other workspaces, other editor profiles' persisted view preferences and user-copied exports are outside this scope; an active or uncertain foreign lease refuses maintenance. Only canonical private owned regular files with one link are removed. Symlinked artifacts refuse deletion rather than following their targets.

Installed hook commands carry an expected collector generation. Reset disables publication, removes the old generation's inbox directory, rotates the collector ID and keeps publication off. A cached pre-reset command cannot publish into the new generation; an old envelope is rejected by namespace validation. An already-open old inbox cannot become the replacement inbox. An interrupted-reset marker is synced before deletion begins and blocks normal replay/enable until a fresh reviewed reset completes. Unknown contents in an old generation can prevent safe completion; they are preserved and the pending reset stays explicit. This is scoped filesystem deletion, not secure physical erasure, and it does not isolate malicious processes running as the same user.
