# Local history and recovery

T19 engineering verification completed 25 October 2026 on macOS arm64. Native collection remains the six-name fixture profile; these storage tests do not establish additional native delivery.

The journal syncs every accepted record before removing its inbox copy. Sequence numbers increase across pruning and restarts. A duplicate UUID must have the same envelope digest; conflicting content is rejected. A process test kills the collector after record sync/before acknowledgment, and another kills it after retention metadata sync/before old segment deletion. Both recover without a second durable effect.

Defaults retain at most 100 MiB of source journal, 100,000 records and seven days, using complete segments of at most 5 MiB. Age pruning also runs during idle scans. Whole-segment retention can remove newer records sharing an old segment when size/count limits require it. A manifest is committed before deletion; obsolete files left by a crash are ignored and removed by the next exclusive owner. Pruning rebuilds source projections/identities/lifecycles and invalidates frozen presentation and open details. Source Health discloses the retained starting sequence.

Recently removed UUIDs retain only digest, receipt time and sequence for idempotent acknowledgment within the seven-day receipt horizon. The bounded 100,000-entry tombstone set cannot evict eligible identities merely to make room; collection stops with a visible transport failure if that safe limit is exhausted. Unknown inbox records older than the horizon are acknowledged as expired without projection or a fabricated sequence. This is bounded history, not an archive.

The 100 MiB limit covers journal segments, separately from the bounded retention manifest (24 MiB read limit), projection cache (16 MiB), inbox and other metadata. The existing producer inbox cap is independent. No rejected payload quarantine or unbounded raw error log is introduced.

Clean disable quiesces ingestion before writing a versioned checkpoint of at most 5,000 normalized tail records. It binds the current privacy policy, source-record digest, sequence range and projection digest. Reenable always validates the complete authoritative journal, including older rows outside the live projection. Missing, malformed, stale or mismatched caches fall back to source replay. These checks detect accidental cache corruption; the same operating-system user is not a cryptographic isolation boundary.

T22 now keeps full payloads for only the newest 5,000 source records. Older retained records remain on disk and are represented in memory by a bounded UUID lookup plus compact SHA-256/sequence/time chunks. Source Health distinguishes retained record count, buffered count and buffered starting sequence; older records are explicitly outside current view/export counts. `Journal.readHistory(afterSequence, limit)` reads and validates a disk page of at most 5,000 rows without retaining the whole journal. This is an internal history API, not a new historical-browser UI. Per-record digests continue to reject conflicting retries even after their payload leaves memory. Pruning preserves the existing crash ordering and deduplication horizon.

Replay reads segments in 64 KiB chunks, preserving UTF-8/record validation across chunk boundaries. Only the last unterminated suffix is recoverable; older malformed rows still fail closed. The live projection follows sequence numbers rather than a moving array offset, so fresh records continue to project after the 5,000-entry tail fills. These changes reduce retained payload memory but do not satisfy the current 75 MiB peak RSS target; see [T22 measurements](performance.md).

Only a final unterminated suffix is truncated, synced and disclosed as a recovered-tail gap. Complete malformed records, missing retained middle segments, invalid manifests and middle corruption stop collection. Source Health reports an allowlisted integrity category without raw errors or payloads. Preserve history for inspection; restore a reviewed known-good backup or use the [T23 reviewed scoped history deletion](privacy.md#reviewed-workspace-history-deletion-t23) commands. A pending interrupted reset also blocks replay until reviewed completion. Never silently skip complete damaged records or infer missing facts from current files.

Validation: 141 unit tests, 17 actual process tests and [34 installed Cursor checks](t19-extension-host-verification.json). The [2,000-record measurement](t19-replay-measurement.json) records hardware, build runtime, bytes, source validation and cold/checkpoint projection times. It is one synthetic sample, not native latency or a general speedup claim. Reproduce after `npm run build` with `node scripts/measure-replay.mjs`.
